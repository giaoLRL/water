# 智能水循环监测与温控物联网系统

依据《智能水循环监测与温控物联网系统》赛题实现的完整系统：现场 ESP32 采集控制端 +
FastAPI 后端 + MySQL + Vue 3 前端，覆盖「感知层 - 网络层 - 平台层 - 应用层」全栈链路。

## 现场设备（真实接入）

采集控制端默认地址 **`http://192.168.31.100`**，烧录固件为《YF-S401 水流量检测》。

| 通道 | 接口 | 状态 |
| --- | --- | --- |
| 瞬时流量 | `GET /api/data`、`/api/flow` | ✅ L/min |
| 累计水量 | `GET /api/data`、`/api/volume` | ✅ L |
| 水泵开关 | `GET /api/pump/on`、`/off`、`/toggle`、`/state` | ✅ |
| 定量浇水 | `GET /api/pump/target[?value=2.5]` | ✅ 达到目标固件自动关泵 |
| 累计清零 | `GET /api/reset` | ✅ 破坏性操作 |
| 设备健康 | `GET /api/health` | ✅ uptime / IP / RSSI |
| **液位(超声波)** | `GET /api/level` | ✅ 单路，**接在加热槽**（百分比）；储水槽无传感器 → 水位恒为 0 |
| 水温 ×2 | `GET /api/temperature` `/api/temperature2` | ✅ 探头1→储水槽、探头2→加热槽 |
| 压力 | `GET /api/pressure` | ✅ 固件单位 MPa，后端统一换算 kPa |
| 加热模块 | `GET /api/heater/*` | ✅ 开关 / 状态查询 |
| 光照 | `GET /api/light` | ✅ GY-302，单位 lx |

> ⚠️ 现场固件会持续升级，通道以实测为准（`/api/health`、`/api/data`、设备首页 `GET /`）。
>
> 本系统为 **纯真实模式 + 按能力裁剪**：能力关闭的通道不采集、不告警、不展示。
> **无数据一律保持 0（水位类）或 `null`（其他通道），不做任何模拟**，
> 并在界面明确标注原因（「无传感器」/「离线」/「设备不支持」）。
>
> 能力开关集中在 `backend/config.py` 的 `DEVICE_FEATURES`，固件变化时改这一处即可。

## 功能特性

- **实时监控（全卡片网格，首屏零滚动）**：页面整体是一个可编辑的 gridstack 卡片网格——
  瞬时流量 / 累计水量（带迷你趋势）、双水温 / 水压 / 光照、**单水槽可视化卡**（罐体水面随
  水位升降）、水泵/加热开关卡、定量浇水卡等全部为卡片，1366×768 以上分辨率**无需滚动**。
- **可编辑仪表盘（免改代码自由组合）**：有 `cfg_system` 权限的账号可进入「编辑卡片」模式
  拖拽/缩放/删除任意卡片；「+ 添加卡片」目录按设备能力与权限自动列出可选项——内置卡片
  （含通用单水槽、控制开关、定量浇水、恒温 PID、最近操作、清零累计、设备健康）与
  **自定义 GET 接口**（全部卡型可添加，可先预览取值）。**每张卡的接口都能改**：配置里
  「接口 URL」留空读本机实时快照、填了走后端代理轮询（白名单防 SSRF）；**控制卡可改指令**：
  自定义开/关两条 GET 指令 URL，经代理下发并写入操作日志。布局全局共享、即改即存，
  刷新后保持；可一键恢复默认（默认布局不含清零卡，危险操作降权）。
  **布局防误覆盖**：每次保存/恢复默认前，后端自动把上一版备份为「上一次布局」，
  编辑模式下可一键「恢复上一次」（可反复点击在最近两版之间来回切换）；保存时会带上
  载入时的布局版本号，若布局已被其他窗口修改，后端拒绝覆盖并提示刷新（错误码 40009），
  避免"停在旧布局的页面点一下保存就把别人的改动冲掉"。
- **双水槽实时水位**：储水槽与加热槽各一张单水槽卡，罐体水面随水位升降、卡内大字百分比与
  估算水量。⚠️ 液位**不做任何模拟**：加热槽为超声波实测值；储水槽无传感器，水位**恒显示 0** 并
  标注「无传感器」；设备离线时两槽水位统一归 0 并标注「离线」。接口用 `source: "device" | "none"`
  区分来源。
- **远程控制**：水泵开关真实下发到现场设备，并回读真实状态；指令失败返回 40003，不伪造成功。
- **定量浇水**：设定目标水量，达到后由设备固件自动关泵；界面显示本次定量进度条，
  支持取消定量与累计水量清零（二次确认）。
- **历史数据**：按时间范围查询，折线图展示流量与累计水量趋势，支持自定义时间段。
  区间数据超过图上点数上限时后端**等距降采样**（首尾保留、曲线始终覆盖到最新数据），
  并在图上方提示「区间共 N 个采样点，图中显示 M 点」。
- **数据统计**：区间平均/最高/最低流量、**按时间加权的平均流量**、区间用水量、累计水量；
  采样点数区分「总行数（含设备离线空行）」与「有效读数点」，避免把离线空行当有效数据。
  区间数据可一键导出 CSV（UTF-8 BOM，Excel 直接打开）。
- **异常告警**：流量/水温/水压/光照阈值上下限可配置，超限即弹窗提示并入库；恢复后自动置为已恢复。
- **报警联动（卡片即来源，免二次配置）**：在系统配置页配置「实时监控页哪张卡片的阈值 → 触发哪张卡片的动作」：
  触发源与动作**都直接从实时监控页的卡片里选**（内置卡或后来自己加的卡都行），不需要再单独维护
  一份执行器档案/通道清单。触发源可选流量/双温/水压/光照等数值卡、水槽卡，以及自定义接口卡
  （后端按卡片周期自动轮询）；动作可选控制开关卡（自定义指令 URL 或内置水泵/加热）与定量浇水卡；
  每条规则自带阈值与方向，越限沿触发、回正常沿可选恢复动作。指令经后端代理下发（白名单主机）
  并写入操作日志（来源标注为系统自动），全程可审计。
- **传感器通道（卡片即声明）**：
  - 加一张「自定义接口」卡（URL+取值路径+轮询周期+单位）→ 后端按周期轮询该接口并入库；
  - 加一张读**本机快照**的数值卡/曲线卡/单水槽卡（如水位、信号强度等非标准列路径）→ 后端按周期取样入库，
    通道 id 为 `card:<卡片id>`；
  两者都会让**历史曲线页出现对应标签、统计页出现指标卡、联动触发源里直接可选**，删卡即停止采集，
  **不需要在系统配置页重复声明**。（流量/累计/双温/水压/光照/泵加热状态/定量目标本来就在逐秒入库，不重复存。）
- **历史曲线**：除流量、累计水量、双温、水压、光照外，新增**水泵状态 / 加热状态 / 定量目标**三条曲线
  （开关量按 1/0 台阶展示，`unknown` 断开），以及所有派生通道（各水槽水位等）——"泵什么时候开过、
  开了多久"可以直接从曲线上看出来。
- **组合条件与持续判定**：联动规则支持附加条件（多条「且」，最多 5 条）与「持续 N 秒才触发」，
  例如「温度 > 40℃ 且 流量 < 5 L/min 持续 10 秒 → 关泵」；任一条件读数缺失时跳过本轮，不误报不误恢复。
- **定时任务**：每天某时刻或每 N 秒自动执行一组「卡片动作」（开/关某执行器、取消定量等），
  与报警联动共用同一套执行器与审计日志（来源标注「系统 · 定时任务」）。
- **通道标定**：工程值 = 原始值 × 系数 + 偏移；提供两点标定（输入两组「原始值→工程值」自动算出系数），
  换传感器（脉冲流量计 K 值、压力零点、温度偏差）后不用改代码，实时快照/入库/告警全部按新系数换算。
- **外部设备接入（Modbus / 串口）**：支持 Modbus TCP(502)、串口服务器(RTU over TCP) 与本机串口，
  在系统配置页填 IP、从站号、寄存器地址、数据类型（u16/s16/u32/f32 及字交换）与换算系数即可接入
  RS485 传感器；读数可映射到本机通道或自定义通道（历史/统计/联动全链路可用），
  也可用「写线圈」接口把 485 继电器板当作控制卡片执行器。现场自测可用 `backend/tests/modbus_sim.py` 模拟从站。
- **判定服务报文模板化**：组委会的判定服务地址、请求头与三段报文（上报/轮询/反馈）都可在网页上填写，
  报文字段用 `{{占位符}}` 映射实时数据；未填写的段落自动回退内置报文。配套
  `backend/tests/mock_judge.py` 可在本地先跑通上报-指令-反馈全流程。
- **历史回放**：历史页可将任意时间范围抽成时间轴，滑块或自动播放在只读面板上回放当时的
  流量/累计/双温/水压/光照与泵、加热状态（按时间点向后端取快照）。回放时**曲线上有一条随时间移动的游标**
  （吸附到最近的曲线点并显示当前时刻），**曲线随之"生长"**——已回放的部分是实线，尚未回放的部分以淡色轮廓保留，
  并且**视口自动跟随**滚动到游标位置：既看得到"正在回放到哪"，也不丢整段趋势。
- **数据导出与一键提交**：历史、告警、操作日志三页都能一键导出 CSV（UTF-8 BOM，Excel 直接打开不乱码）；
  `scripts/make_submission.ps1` 一键生成规程要求的「技能赛提交文件」文件夹（源码+文档+数据导出+提交说明）。
- **系统拓扑卡与一键场景卡**（内置卡，编辑模式添加）：拓扑卡用 SVG 展示水循环回路，
  节点颜色/水位/管路流动随实时数据变化，无传感器槽位明确标注；场景卡提供「启动循环」与
  「急停全部」（关水泵、关加热、取消定量，并依次关闭所有自定义执行器），均二次确认并写操作日志。
- **恒温闭环（多路，卡片即来源）**：一张「恒温闭环」卡 = 一路独立 PID，卡里指定
  **温度来源卡**（本机温度卡、自定义接口卡、其他数值卡）、**加热执行器卡**（内置加热/水泵卡，
  或带开/关指令 URL 的自定义控制卡，也支持 485 继电器）与可选的**防干烧联锁卡**（如液位 ≥ 阈值，
  不满足强制断开加热）。多水槽各自控温就加多张闭环卡，各路目标温度与 Kp/Ki/Kd 独立、互不影响；
  未指定来源/执行器的老式闭环卡继续按默认回路（加热槽水温 → 本机加热）运行。
- **操作日志（可审计）**：记录**谁在什么时候做了什么**，覆盖三类操作——
  设备控制（水泵/定量/清零）、系统配置（告警阈值/采集周期/水槽容积）、账号管理（创建/删除/改角色/重置密码/权限矩阵）。
  系统自动动作（恒温闭环、判定服务下发指令）没有操作账号，标注为「系统 · 恒温闭环」/「系统 · 判定服务」，
  与人工操作明确区分；支持按分类筛选。**不记录任何密码明文。**
- **账号与权限**：JWT 登录 + 可自定义的角色权限矩阵（管理员 / 运维 / 观察员等）。
- **判定服务对接**（任务五）：按 1Hz 向组委会判定服务上报、轮询指令、回传执行结果。
- **多终端自适应**：PC 与手机端自适应布局。

## 技术栈

| 层次 | 选型 |
| --- | --- |
| 前端 | Vue 3（本地库，无构建）+ ECharts + gridstack（可编辑卡片网格），PC / 移动端自适应 |
| 后端 | Python 3.11+ FastAPI + Uvicorn（自带 `/docs`） |

## 快速启动

> 本机（Windows）已部署完成：完整流程、启停命令、配置修改与故障排查见
> [`部署指南.md`](部署指南.md)（所有命令均已实测）。

### 1. 启动数据库

本地 MySQL 需已就绪（创建 `iot_system` 库及 `iot_user` 账号）：

```sql
CREATE DATABASE IF NOT EXISTS iot_system DEFAULT CHARACTER SET utf8mb4;
CREATE USER IF NOT EXISTS 'iot_user'@'127.0.0.1' IDENTIFIED BY 'iot_pass_2026';
GRANT ALL ON iot_system.* TO 'iot_user'@'127.0.0.1';
FLUSH PRIVILEGES;
```

建表与表结构迁移由后端启动时自动完成（幂等，不丢历史数据）。

### 2. 安装依赖并启动后端

```powershell
python -m pip install -r backend\requirements.txt
cd backend
python main.py
```

启动日志会打印采集设备地址、已启用的通道，以及 PID 是否因设备不支持而禁用。

浏览器访问 <http://127.0.0.1:8000>，接口文档 <http://127.0.0.1:8000/docs>。

### 3. 环境变量（可选）

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `IOT_DB_HOST/PORT/USER/PASSWORD/NAME` | 127.0.0.1 / 3306 / iot_user / iot_pass_2026 / iot_system | 数据库连接 |
| `WATER_DEVICE_URL` | `http://192.168.31.100` | 现场采集控制端地址 |
| `WATER_DEVICE_TIMEOUT` | `1.5` | 单次设备请求超时（秒） |
| `WATER_DEVICE_OFFLINE_AFTER` | `5.0` | 连续无响应多久判定离线并清空读数 |
| `WATER_SAMPLE_PERIOD` | `1.0` | 采集周期（秒），须 ≥1Hz |
| `WATER_JUDGE_URL` | 空 | 判定服务地址；留空则不上报 |
| `WATER_DASHBOARD_PROXY_HOSTS` | 本机/localhost/设备主机 | 自定义卡片接口的代理白名单（逗号分隔追加主机） |

设备地址、能力表、告警阈值等现场参数集中在 `backend/config.py`，均用【现场修改】标注。

## 核心接口

统一返回格式：`{"code": 0, "msg": "ok", "data": {...}}`。

| 接口 | 方法 | 功能 |
| --- | --- | --- |
| `/api/water/realtime` | GET | 实时数据（流量 / 累计水量 / 水泵 / 设备状态 / 能力表 / 活跃告警） |
| `/api/water/history?start=&end=` | GET | 历史传感数据查询 |
| `/api/water/stats?start=&end=` | GET | 统计指标（流量均值极值、区间用水量、采样点数） |
| `/api/water/pump` | POST | 水泵控制 `{"action":"on\|off\|toggle"}` |
| `/api/water/pump/target` | GET/POST | 查询 / 设定定量浇水目标 `{"liters":2.5}` |
| `/api/water/volume/reset` | POST | 清零累计水量（破坏性，需权限） |
| `/api/water/device` | GET | 设备链路信息（在线 / IP / RSSI / 运行时长 / 支持通道） |
| `/api/water/tank` | POST | 设置水槽容积 `{"tank":"storage\|heater","capacity":1000}` |
| `/api/water/system` | GET | 系统状态（数据库、采集周期、设备地址与在线状态） |
| `/api/water/alarm/config` | GET/POST | 告警阈值读写（当前为流量上下限） |
| `/api/water/alarms` | GET | 告警记录查询（分页） |
| `/api/water/logs?category=&page=&page_size=` | GET | 操作日志（含操作人与来源；category=device/config/account） |
| `/api/water/dashboard/layout` | GET/POST | 仪表盘布局读取 / 保存（全局共享；保存需 cfg_system） |
| `/api/water/dashboard/layout/reset` | POST | 恢复默认布局（需 cfg_system） |
| `/api/water/dashboard/proxy?url=` | GET | 自定义卡片接口代理（仅 GET/JSON，主机白名单防 SSRF） |
| `/api/water/ingest` | POST | 采集端主动上报（可选链路） |
| `/api/water/custom/history`、`/api/water/custom/stats` | GET | 自定义通道历史曲线与统计指标（通道=实时监控页的自定义接口卡，按卡片 id + 时间范围查询） |
| `/api/water/alarm/links` | GET/POST | 报警联动规则读写（触发源/动作均引用实时监控页卡片） |
| `/api/water/export.csv` | GET | CSV 导出（kind=sensors/alarms/logs/custom，UTF-8 BOM） |
| `/api/water/timers` | GET/POST | 定时任务（每天某时刻 / 每 N 秒执行卡片动作） |
| `/api/water/calibration`、`/api/water/calibration/two_point` | GET/POST | 通道标定与两点标定计算 |
| `/api/water/gateway`、`/api/water/gateway/test`、`/api/water/gateway/coil` | GET/POST | 外部设备接入（Modbus TCP / 串口服务器）：配置、试读、写线圈 |
| `/api/water/replay`、`/api/water/replay/frames` | GET | 历史回放（按时间点取快照 / 时间轴帧序列） |
| `/api/water/judge/template` | GET/POST | 判定服务地址与报文模板（headers + report/poll/feedback） |
| `/api/water/pid/loops` | GET/POST | 恒温闭环回路状态 / 更新某路目标温度与 PID 参数（写回卡片配置） |
| `/api/water/dashboard/layout/restore_prev` | POST | 一键恢复「上一次布局」（保存/重置前自动备份，可反复点击在两版间切换） |
| `/api/auth/login` | POST | 登录获取 token |
| `/api/auth/users`、`/api/auth/roles` | GET/POST | 账号与角色权限管理 |

默认管理员：`admin` / `admin123`（首次启动自动创建，请及时修改）。

已按设备能力停用：`/api/water/heater`、`/api/water/target`、`/api/water/pid/*`
（均返回 40003「当前采集设备不支持该通道」）。

## 现场注意事项

- **储水槽液位传感器接入后如何切换为实测值**：把 `backend/config.py` 的
  `DEVICE_FEATURES["level_storage"]` 改为 `True`，并按固件实际接口填写
  `LEVEL_PATH_STORAGE`（当前加热槽用的是 `/api/level`）
  与 `TANK_HEIGHT_CM_STORAGE`（水槽高度，cm）。
  采集端支持返回百分比（`unit:"%"`）或厘米（`unit:"cm"`/`"mm"`，自动按高度换算）。
  改完重启后端即可，界面会自动由「无传感器 / 0」切换为实测值；两槽可分别接入，互不影响。
- 现场实测本水循环回路流量约 **21~82 L/min** 且波动很大（2 秒内可从 16 跳到 82），
  `flow_max` 默认取 `80.0`；**实测已出现 81.9 L/min 的尖峰，可能触发误报**，
  建议按实际工况上调（如 120），或改为对流量均值告警。
- 现场设备存在 **`pump` 状态与真实水流不一致** 的现象（实测水泵状态为 `false` 时
  流量仍达 20~50 L/min、累计水量持续增长）。后端如实反映设备上报值，未做掩盖；
  请现场核对水泵供电与控制接线。
- **定量完成后设备会自动清零**：实测设定定量目标并完成后，固件会把 `totalLiters`
  复位为 0 并清除 `pumpTarget`。这是固件行为，后端与界面已按此处理（进度条会回退）。
- ESP32 偶发单次请求超时或连接被重置（实测约几分钟一次）。后端设计为：单次失败保留上一次读数
  并标记离线，连续超过 `WATER_DEVICE_OFFLINE_AFTER`(默认 5s) 才清空读数，避免界面数据闪烁。
- 加热模块无水位保护时严禁无水通电，避免干烧扣分。
